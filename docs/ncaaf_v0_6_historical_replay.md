# NCAAF v0.6 Historical Replay Infrastructure

This infrastructure is replay-only. It does not modify frozen production
`project_ncaaf_from_apex.py`, invoke the production ratings updater, write
`models/ncaaf_power_ratings.csv`, write `sample_model_edges.csv`, create a
production `model_run`, or modify Apex model/evaluation tables.

## Validation split

- Development: 2022-2024
- Historical holdout: 2025
- Forward validation: 2026+

The replay runner defaults to `--mode development`. Season 2025 is rejected
unless the caller explicitly supplies both:

`--mode holdout --unlock-holdout 2025`

No calibration report is generated by this infrastructure.

## Ratings archive

A normalized weekly ratings snapshot has these columns:

`season,source,source_label,source_url,published_at,target_week,safe_after,team,rating,ratings_sha256`

`published_at` is the actual known publication/availability time.
`safe_after` is the conservative earliest timestamp at which the snapshot may
be used. It must be at or after `published_at`.

The normalized snapshot SHA is calculated over the normalized rows excluding
the `ratings_sha256` column. Every row carries the same SHA. Missing ratings are
never inferred.

Use `build_ncaaf_historical_ratings_snapshot.py` to create an immutable snapshot
directory. When an original HTML/PDF/text artifact is available, pass it with
`--source-artifact`; it is copied into the snapshot directory separately from
the normalized CSV.

## Anti-leakage enforcement

For each replay:

1. ratings season must equal replay season;
2. ratings `target_week` must equal replay week;
3. `replay_as_of >= ratings.safe_after`;
4. each game's kickoff must be strictly after `ratings.safe_after`;
5. each game's kickoff must be strictly after `replay_as_of`.

Therefore a snapshot described as "post-Week N" cannot be used to forecast a
Week N game if its actual publication/safe timestamp occurs after that game's
kickoff.

## Historical game/line input

One row per game/provider:

`event_id,season,week,kickoff,home_team,away_team,provider,home_spread,home_spread_price,away_spread_price,opening_home_spread,home_score,away_score,line_source`

Spread convention matches the prior CFBD backtest:

- negative `home_spread` = home favorite;
- positive `home_spread` = home underdog;
- away spread is derived as the exact inverse.

Price fields may be blank. The runner uses -110 only as an internal compatibility
value when calling the frozen production selector; missing historical price stays
blank in replay output and does not block forecast-error analysis.

## Season-aware eligibility

Replay requires a separate season-aware eligibility CSV:

`season,display_team,model_team,classification,source,source_url,notes`

`classification` must be `fbs` or `fcs`.

The runner does not load the production `ncaaf_team_mapping.csv`. Instead it
constructs the mapping passed to frozen v0.6 from the selected historical
season. It also temporarily replaces the production module's in-memory
`FCS_TEAMS` set, if present, with the historical season's FCS set while replaying.
The production source file itself is never edited.

Rows missing season eligibility are excluded rather than silently falling back
to present-day classification.

## Frozen v0.6 reuse

`replay_ncaaf_v0_6.py` imports `scripts.project_ncaaf_from_apex` and calls its
existing `build_model_row_for_event()` directly. That preserves the frozen
projection, side selection, thresholds, recommendation, confidence, guard and
unit logic.

The production module's in-memory `datetime` symbol is temporarily replaced
during each call so its existing future-game guard evaluates against the
historical `replay_as_of`, not today's clock. It is restored immediately after
the call. No production source file is changed.

## Immutable replay artifact

The specified output directory must not already exist. A completed replay
contains:

- `inputs/` copies of ratings, game/line and eligibility inputs;
- `rows.csv`;
- `exclusions.csv`;
- `replay_manifest.json`.

The manifest records input hashes, ratings provenance, replay as-of, provider,
line source, frozen production-script SHA, ApexModel Git commit, counts,
exclusion reasons and output hashes.

## Output rows

Rows include:

- immutable event ID, season/week/kickoff;
- home/away and selected side/team;
- provider and line source;
- historical market line and available price/opening line;
- frozen v0.6 model line, edge, recommendation, actionability, confidence and units;
- final scores when supplied;
- actual selected-side margin;
- signed and absolute model forecast error;
- market absolute error;
- ATS result;
- ratings provenance/hash;
- replay as-of;
- frozen production code SHA.

## Typical development replay

Example shape:

`py scripts\replay_ncaaf_v0_6.py --ratings <normalized.csv> --games-lines <week.csv> --eligibility <eligibility.csv> --season 2023 --week 5 --replay-as-of "2023-09-25T12:00:00-04:00" --provider DraftKings --output-dir outputs\replays\ncaaf_v0_6\2023\week_05\proof_001`

Add `--validate-only` to perform all input, anti-leakage, eligibility and frozen
production checks without writing replay artifacts.
